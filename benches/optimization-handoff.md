# tblgen 优化任务：给下一位 Agent 的 Prompt

你负责 Rust 工具 `tblgen` 的一项可评估优化。**只选一个任务 ID，不要实现整张清单。** 先回答“哪段工作值得减少”，再回答“如何写得更快”。假设被推翻、因收益太小而不合入，也是有效交付。

## 开工前

- 目标是含 `src/gen.rs` 和 `benches/wire_check.rs` 的 **tblgen**，不是 `metadata-checker`。先核对仓库名、所在提交、工作区改动、适用的 AGENTS 与执行环境约束。不要拿另一个仓库的命令、远端环境、性能数字或目录结构当作本项目的证据。
- 先读 `benches/check-ablation.md`、`benches/partition-spike.md`、`benches/README.md`；需要具体数字时用同目录 JSON 原始样本。上一轮的基线包含未提交的语义修复和优化，不能用裸 `HEAD` 代替。记录本轮基线的源码、lockfile、工具链、输入指纹。
- 保留前驱字段名缓存、顺序匹配失配后才建索引的输出分区查找、错误路径延迟格式化。逐一撤回，在 1,062 份文件上的纯 wire 校验分别慢了 **353.0%、30.6%、11.2%**，三个变体均未改变诊断。它们是对照，不是待做事项。
- 最有信息量的两个起点：关闭 Select 步骤检查使修复后实验模型的纯检查耗时下降 **73.4%**，但会使真实语料中 **39 个**原有错误的文件错误归零；关闭血缘检查使整批纯检查耗时下降 **43.8%**，同时丢失 **101 条错误、9,198 条警告**。这些是整组消融差值，含诊断构造等开销，**不是**某个函数的独占 CPU 占比，更不是可无损取得的收益。
- 1,062 份服务端文件用于验证真实 wire、CLI、诊断与往返保真。上次这些文件均走 archive；**不能拿它们证明 typed 生成或 typed 反编译加速**。typed 链路另用 `tests/fixtures/experiment.spec.json`、仓库示例与生成的 DAG。外部语料和 BI Java 源码只在可访问且获授权时使用；缺失时明确写“未验证”，不上传语料、不伪造全量结果。

## 可领取任务

优先级是投入顺序，不是对收益的承诺。下列“测”给出能区分候选方案的实验；一个 ID 内有多个想法时，也只改变一个因素。

### 第一批：有消融证据，或能决定后续投向

| ID | 入口与假设 | 最小实验和验收重点 |
|---|---|---|
| **S1 · Select 步骤** | `check_select_steps`、`model::evolve_names`。将“有序名字列表”与“当前名字是否存在”分开；仅在名称变动时更新查找索引。 | 首先分别统计名称比较、全列表复制、表达式解析、诊断构造次数。固定字段宽度改变步数，再固定步数改变宽度；覆盖长串 Filter、频繁 rename/remove、大小写与重复名。顺序、冲突位置、opaque 步骤后的行为不变。 |
| **S2 · 表达式引用** | `model::exp_bracket_refs`、Select/Join 的消费者。相同表达式是否被重复扫描、分配或折叠？ | 比反复使用同一表达式与每步唯一表达式；分别试借用切片、单次编译期缓存。区分字段、参数与表限定符，保留现有词法边界；记录缓存内存与命中率。 |
| **L1 · 血缘成本分解** | `src/check/lineage.rs`。前驱字段集合已缓存，剩余工作可能在逐字段解析前驱、重复转大写、诊断文本和指针。 | 用同样大小的图，一组来源全合法、一组产生警告，再与真实语料对照。先分离查找与报错成本，再试按当前节点索引直接输入的别名/键。相同别名的不同 wire ID 不得串数据，不能退化为全局别名查找。 |
| **L2 · 血缘警告质量** | 9,198 条 `warn.field.originalNode` 是否可操作？这是规则质量审计，**不是**性能改动。 | 按节点类型、同名别名、计算字段、跨多跳来源分层，固定抽样清单；用 Java 加载/运行时规则与人工判读标记“有效、疑似误报、不可验证”。交付匿名计数、代表性反例；不因数量多而静默、去重或降级。若要改规则，另立语义变更。 |
| **C1 · CLI 分段计时** | `main::cmd_check`、`check_file`、`expand_dirs`。完整 CLI 还包括枚举、读盘、解析、项目引用与报告输出。 | 同一文件清单，区分冷/热缓存，分段测墙钟、CPU、分配/峰值 RSS、输出字节数；比较少诊断与多诊断文件。不能简单用“CLI 减纯 wire”命名为 JSON 解析时间。决定 C2–C5 谁先做。 |
| **C2 · 项目引用 I/O** | `check_references`、`project::locate/resolve_reference/to_disk`。消融整组曾使 CLI 更快 6.4%，也少报 20 条错误，不能跳过。 | 统计 canonicalize、metadata、同一目标重复探测次数；试单次批处理内按项目根和规范路径复用结果。专测跨项目、同名相对路径、目标不存在、不可验证与符号链接；不得把读路径的缓存复用到写前安全检查。 |
| **C3 · 报告构造与输出** | `cmd_check` 先收集报告，再建 JSON 并序列化。比较借用式序列化、缓冲写、按文件保序输出。 | 固定文件数，改变警告密度，分别计 CPU、峰值 RSS、总耗时。和基线逐字节对 stdout，并比较 stderr、退出码、I/O 失败与输出顺序；默认格式不变。 |

### 第二批：typed gen 与 decompile，必须先建各自基准

| ID | 入口与候选 | 区分方案的输入／不能改变的行为 |
|---|---|---|
| **G0 · typed 阶段基准** | `compile_generated` 已将准备与构建合并为一次编译；分别计 `validate_generated`、字段计算、wire 发射、最终 `check`、诊断回映。 | 小 spec、实验 spec、宽表、深链、扇入/扇出、错误密集 spec 分开；输入只解析一次。不要再提“去掉已经消除的双编译”。 |
| **G1 · Select 重复推演** | `check_select_step_fields`、`check_select_explicit_vs_derived`、`simulate_select`、`apply_step_mutation`。测重建名字列表/steps clone 与重复求值；试一次推演产出名称变化、字段和 step hints。 | 显式与隐式投影，连续 Add/Transform/Refactor，opaque/rawStep。保留 `exp`、原始血缘、显式输出顺序和 editor hints；wire 合法的部分投影不等于 typed spec 可不一致。 |
| **G2 · 字段匹配与多重集** | `find_pred_field`、`name_multiset_eq`、显式声明对派生结果的匹配。比较逐项找/删除与按大写名计数或直接索引。 | 同序、逆序、重复计数不等、Unicode 大写后碰撞。索引查成员，原 `Vec` 定顺序；不得用集合误代多重集。记录小表建索引的反效果。 |
| **G3 · Join / Union / Distinct / Output 投影** | 各 `compute_*_fields`：预索引前驱字段、直接输入别名、Union 映射行，避免为每个输出列再扫描输入和整张映射。 | 多输入、首输入空映射、别名不同于键、重命名、隐藏行、同名列及歧义。验证所有输出字段与错误路径，不只比列数。 |
| **G4 · 稳定拓扑与图布局** | `topo_sort` 的有序 `Vec` 出队/插入会搬移；试按声明索引的小顶堆、邻接索引，以及按排序索引移动而非复制 `NodeDesc`。 | 比链形、星形、大量同时 ready、刚解锁的小索引、环和缺失输入。保留“从当前 ready 中取声明最早者”，不是一般 FIFO；小图同测。 |
| **G5 · 诊断回映** | `map_wire_diag` 对诊断逐个匹配并转义 `wire_key`。试延迟构建一次 escaped key → descriptor 索引，减少中间字符串复制。 | 0、1、大量诊断；键含 `/`、`~`，覆盖 `/config`、`/raw`、`/rawNode` 和字段下标。严重度、来源与诊断顺序逐条一致。 |
| **G6 · JSON 所有权/内部表示** | `prepare_nodes`、`build_generated_collect`、`partition_fields`、`emit_typed_node`：先抓分配剖面，再逐个消除 `Value` 深拷贝、借用只读字段、move 一次性产物。最后才评估轻量 typed IR、整数 ID 或局部字符串驻留。 | 深链与 fan-out 都测分配字节和峰值 RSS；不要为减少 clone 反而长期持有整份树。raw 逃生通道不能强制类型化。 |
| **G7 · 阶段间共享已验证事实** | 评估编译阶段共享不可变图/名称索引的收益；可以先仅记录重复次数。 | **保留独立、公开的 `check(&wire)` 防线**，不得令生成器与校验器共同相信同一份未经 wire 验证的结论。拿 rawNode、错误发射的反例证明检查仍会失败。 |
| **D1 · 反编译的失败路径** | `try_generated → generate → normalize/compare → archive_form`。先计候选成功、尝试后失败、直接 fallback 的比例与各段成本；试可证明不可能 typed 的早退。 | 真正 typed 成功、真实 archive、rawTable、畸形 DataFlow 分开跑。已有可 typed 重建的输入不得仅为提速转入 archive；无效文档不能被归档成“成功”。 |
| **D2 · 精确等价比较** | `decompile::normalize` 会克隆整棵树；试借用式递归比较，仅在原路径忽略已经允许的 `dataFlow.nodes.*.lastModifyTime`。 | 只有该键不同、同名键出现在别处、深层单字段不同、数组顺序不同、大数。不能用哈希相等代替精确比较；archive/rawTable 往返仍须 JSON 值相同。 |

### 第三批：其余可检验方向，达到前提再投入

| ID | 假设与入口 | 先做什么／何时不做 |
|---|---|---|
| **W1 · 其余 wire 规则** | `check_arity_and_type_rules`、Join/Union、`check_fields`、图与参数准备。尝试每节点一次提取只读视图、复用字段/参数索引，减少重复 JSON 遍历与 String 所有权。 | 按节点类型、字段数、映射稠密度测；保留不同 pass 的诊断顺序。图规则在真实清单没报错并非可删除，悬空输入和环都须保留阳性样本。 |
| **W2 · 分区/提取字段遍历** | 顺序快路径已完成；仅在剖面仍热时评估借用遍历器或共享树遍历。 | 顶层字段、目录/层级、维度/度量交错、乱序、重复、不可见/无效字段。分区检查与 `dbfield` 检查识别叶子和路径的规则不完全相同，不可机械合并。 |

| **P1 · 构建与运行配置** | 在热点已变小时，最后评估 release LTO、codegen units、代表性负载的 PGO、分配器或容器容量策略。 | 独立比较吞吐、启动、构建用时、二进制体积和平台兼容性；训练/评估输入分离。不要把 `target-cpu=native` 的单机成绩当可分发基线，不为微小收益新增重依赖。 |

### 架构任务：与算法修改分开交付

| ID | 拆分边界 | 独立验收 |
|---|---|---|
| **A1 · 生成器** | 将 `gen.rs` 按编排/诊断回映、图和 ID 准备、typed 验证、Select 状态机、节点投影、wire 发射拆分；让 archive/rawTable 保持独立路径。 | 一次搬一条规则或一个职责，保留公开 API 和结果；先做纯搬迁，再做算法替换。tuple 到 `Result<Option<_>, Diag>` 是独立可读性改动，不作为性能成果。 |
| **A2 · 检查器** | 沿用已有 `check/lineage.rs`、`check/output.rs`，优先抽出 `select`，再拆 `graph`、节点专属规则、项目引用与诊断工具。 | 保持调用顺序与验证覆盖；不要为了复用 typed 实现，把合法的真实 wire 部分投影判错。 |
| **A3 · 注册表、schema、CLI 与测试** | `model.rs` 维护共用语义；schema 片段与 examples 分离；`new.rs` 按解析、输入读取、spec 组装拆分。大集成测试按行为拆，保留共享 fixtures/provenance。 | 用一致性测试检查节点/step/config 注册表、schema 与 validator 漂移；typed 与 wire 有意不同的规则明确标注。结构收益用规则修改涉及的职责、重复定义和编译时间评估，不以文件行数或假想提速代替。 |

## 所有任务的交付标准

1. **先定位。** 写下任务 ID、假设、证据级别、候选改动与反证条件。记录当前基线，不重跑已冻结的历史统计来“刷新”结论。多 agent 可并行调查 S1、C1、G0、L2；S1 与 A2、G1 与 A1 等重叠写入不能并行落地。
2. **再实验。** 在允许的构建环境里，固定 release 构建、输入与工具链；预热并交替/均衡执行 A/B，留原始样本、配对中位数与波动。分别报告库函数、CLI、峰值 RSS 或分配（按假设选），明确是否含解析、I/O 和序列化。小输入、代表性真实输入、能放大候选差异的输入都要测。
3. **证明等价。** 性能改动对比逐文件、完整有序诊断（rule/path/message/source/重复项）、退出码、CLI 输出及生成 JSON。保留 `check(gen(accepted_typed_spec))` 零硬错误、wire 顺序与默认 Output、Unicode 大写匹配、Join/Union 别名及来源、Select 表达式和 raw 逃生路径。针对关联语义跑已有反例，再补会区分错误实现的边界用例。没有真实 BI 执行证据，不宣称已在服务端运行验证。
4. **明确停止。** 收益落在噪声内、只在不代表用户的合成数据上改善且代价较大、内存/可移植性明显恶化，或无法证明行为等价：交付结果，**不合入实现**。若要改行为、文案或默认策略，另开任务，不能以“优化”名义捎带。
5. **交付格式。** `任务 ID | 基线/输入指纹 | 唯一变量 | 修改范围 | 原始结果位置 | 收益与代价 | 等价证据 | 已知盲区 | 保留/放弃及下一步`。遵守所在仓库的提交与测试约束；不全仓格式化、不清理既有未提交内容、不动无关 `docs/`、不覆盖原实验输出。
