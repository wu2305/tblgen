# DataFlow 检查器功能消融

**结论：保留校验与三项优化。** 本实验区分“因为不再检查所以快”和“同样的诊断做得更快”。
只测 wire `check(&Value)` 和实际 `tblgen check`；不推断 typed gen、decompile 或 BI 运行时收益。
所有变体只在隔离源码副本内构建，没有产品开关。见[原始计时和逐规则差分](check-ablation.json)。

## 关掉一组检查，会漏掉什么？

基线含上一轮所有优化。1,062 份真实 `.tbl` 的完整 CLI 报告有 974 条错误、9,410 条警告，131 个文件有错误。
“错误归零”指该文件从至少一个错误变成零错误，仍可能有警告；不是把整个批次的退出码从 1 变成 0。
两列耗时都是相对同轮完整版本的配对变化中位数，负数表示消融版更快。

| 单独关闭 | 少报错误 | 少报警告 | 诊断改变的文件 | 错误归零文件 | 纯 wire 耗时 | 实际 CLI 耗时 |
|---|---:|---:|---:|---:|---:|---:|
| `fields` 字段及 originalFields 的对象、名字、类型检查 | 611 | 0 | 20 | 5 | −7.8% | −1.5% |
| `graph` 悬空输入与环检测 | 0 | 0 | 0 | 0 | −3.0% | −1.3% |
| `node_rules` 输入数量、节点专属规则及条件配置 | 137 | 3 | 45 | 37 | −7.2% | −3.5% |
| `select` Select 步骤分析及参数名准备 | 45 | 96 | 81 | 39 | −19.8% | −3.6% |
| `lineage` 字段来源与根来源校验 | 101 | 9,198 | 502 | 0 | −43.8% | −13.2% |
| `partition` 默认 Output 与顶层分区的成员关系 | 33 | 0 | 6 | 2 | −4.8% | −0.5% |
| `extract` 提取字段的 ASCII 物理列名提示 | 0 | 2 | 2 | 0 | −2.9% | +0.3% |
| `references` CLI 项目定位与跨文件引用检查 | 20 | 1 | 16 | 7 | −0.1%（对照噪声） | −6.4% |

- 拒绝文件的独立贡献以 Select 和节点规则最大；字段结构检查的错误最多，却集中在少数文件。两种指标不能互相替代。
- 关闭血缘检查没有使文件错误归零，但会漏掉 101 个 `field.inputField.missing`。9,198 个 `warn.field.originalNode` 占了绝大多数警告；应评估它们是否可操作，而非把警告数等同于发现缺陷数。消融也减少了诊断构造与序列化，13.2% 不能归为血缘算法的独占耗时。
- 真实清单未触发悬空输入或环，不表示图校验可删。单缺陷对照中，只有关闭 `graph` 才让悬空输入诊断消失。节点基础结构、公共图信息构建、重复边提示、其他顶层检查始终保留；各行不是覆盖一切的计时分解。
- 历史实验文件的 18 个错误中，关闭节点规则丢失 10 个 Union 映射错误，关闭 Select 丢失 8 个 AddField 操作数错误。在**修复后**的 38 节点模型中，关闭 Select 使纯检查耗时下降 73.4%。若继续优化复杂模型，应优先测步骤推演，不应关闭它。

## 撤回优化，但保留全部规则

以下三版在全部真实文件上与基线的 CLI 标准输出和退出码完全一致。表中是撤回后的**耗时增长率**，不可相加。

| 只撤回 | 整批纯 wire | 256 列纯 wire | 整批实际 CLI |
|---|---:|---:|---:|
| 前驱字段名缓存，每次重新建集合 | +353.0% | +5,658.3% | +70.4% |
| 分区顺序匹配/失配索引，恢复为 Unicode 逐项扫描 | +30.6% | +648.0% | +4.4% |
| 错误路径延迟格式化，恢复为逐字段预先构造 | +11.2% | +35.2% | +2.7% |

保留前驱缓存的证据最强。延迟格式化在纯校验中有收益，CLI 端差异较小（撤回后 12 轮中有 5 轮反而更快）；不要把该项 CLI 百分比当成稳定保证。

## 协议与复跑

macOS arm64、相同 Rust release 工具链和 lockfile，12 个独立可执行版本：完整版本、8 个功能消融、3 个优化消融。每个实验只改一个因素。
输入为有序真实清单、修复后的实验 wire、256 列合成模型；诊断另用 5 个历史反例、旧实验、1 个干净对照和 8 个独立阳性对照。
所有版本都验证干净对照无诊断；每个阳性样本的目标 `(rule,path)` 只在关闭对应组时消失。
逐文件按严重度比较完整有序诊断（计入重复项）；出现新诊断或重排即中止。这里的“少报”只指相对完整版本，不是人工标注的准确率或召回率。

每个负载先各预热一次，再用 12 轮均衡轮换，使各版本在每个位置出现一次。完整版本中位数：纯 wire 整批 71.98 ms、修复后实验 0.475 ms、256 列 0.126 ms、CLI 整批 370.35 ms。
纯 wire 计时不含解析与文件 I/O；CLI 从启动到接收完整 stdout，包括跨文件访问与报告输出。小差值需结合原始配对方向解读；不从单因素结果推断交互或相加预测联合关闭的收益。

```bash
# WORK 必须尚不存在、且在仓库外；从包含当前未提交修复的工作区冻结源码。
python3 -I scripts/build_check_ablations.py "$WORK"
python3 -IB scripts/run_check_ablations.py "$WORK" "$CORPUS_JSON" "$EXPERIMENT_TBL" > results.json
```

需要 Python 3.10+。`CORPUS_JSON` 为同机可访问的 `.tbl` 绝对路径数组，保留项目布局才能复现引用诊断。
`EXPERIMENT_TBL` 是实验 spec 生成的 wire，不是 spec。构建脚本保存源码指纹、每个变体的精确 patch 和可执行文件；代码锚点失配时会报错，不修改原仓库。
