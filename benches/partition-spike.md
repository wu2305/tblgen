# 输出分区匹配：算法还是 SIMD？

本轮基线**已包含前驱字段索引**。只改变 wire checker，不改变模型、诊断、生成器或 CLI 协议。
原始计时、release 工具链、源码与语料指纹在 [partition-spike.json](partition-spike.json)。

## 从数据选择算法

旧实现把顶层维度和度量分别展平，然后对每个有效 Output 字段做线性查找，每次比较都对两个名字执行 Unicode 大写转换。
1,062 个真实文件中，有 17,026 次成员查询，估计发生 334,272 次候选名比较（按首次大写匹配位置静态计数）。
若分别按维度和度量从头顺序对照，**16,182 次查询可以用原字符串直接命中**。1,548 个实际被查询的分区中，只有 69 个需要回退。

四个候选使用同一输入和完整 `check(&Value)` 计时。下表为各自 8 次测量的中位数，单位 ms。
合成表固定 `ModelTable → Select → Output`，不把全函数差异误作独占 CPU 时间。

| 输入 | 上轮基线 | 线性扫描，精确/ASCII 快速比较 | Unicode 哈希集合 | 顺序比较，失配建索引 |
|---|---:|---:|---:|---:|
| 1 列 | 0.0042 | 0.0040 | 0.0041 | 0.0040 |
| 256 列 | 1.022 | 0.302 | 0.192 | 0.179 |
| 1,024 列 | 13.868 | 2.885 | 0.728 | 0.679 |
| 256 列，乱序、混合文字、嵌套 | 0.900 | 0.732 | 0.215 | 0.211 |
| 同上，每七列缺一项 | 0.921 | 0.763 | 0.231 | 0.223 |
| 38 节点实验模型 | 0.499 | 0.492 | 0.492 | 0.494 |
| 1,062 份真实文件，整批 | 107.91 | 106.77 | 84.62 | 81.47 |

**选择最后一列。** 每个角色独立比较下一个名字。第一次不能逐字节匹配时，为该角色的**整个分区**构建一次 Unicode 大写索引，而不是只索引剩余后缀；因此乱序、重复引用、`Straße`/`STRASSE` 仍按成员关系判断。以名字为单位，最坏排列下的逐项线性搜索变成预期 `O(分区名字数 + 输出字段数)` 的总工作量；不是要求 wire 按固定顺序保存。

**不加手写 SIMD。** 快速比较对全 ASCII 合成宽表有效，却没有消除两层循环；在真实语料上的效果也远小于改变查找算法。17,026 次查询中，仅 1,410 个名字是纯 ASCII，只有 70 个是至少 16 字节的纯 ASCII 名。这里测的是可移植比较方案，不是 NEON/AVX 指令实测，不推断其他平台或 JSON 解析器的 SIMD 上限。

## 独立实验：不为成功路径构造诊断字符串

静态检查字段项时，真实语料会构造 128,937 个字段级 JSON Pointer，其中仅 309 个字段项需要发出相应诊断。保持错误的顺序与路径不变，把 `format!` 放进错误分支，以顺序匹配版为基线重新做独立 A/B：

| `check(&Value)` | 顺序匹配 | 加延迟格式化 |
|---|---:|---:|
| 真实语料整批 | 79.75 ms | 71.55 ms |
| 1,024 列 | 0.644 ms | 0.476 ms |
| 38 节点实验模型 | 0.490 ms | 0.478 ms |

**两项均保留。** 实际执行 `tblgen check`（同一清单作为独立 argv 一次传入，含读盘、引用解析、序列化），直接比较上轮基线与最终版：**396.02 → 362.37 ms**，8 对均更快，配对耗时降幅中位数 8.5%。进程峰值 RSS 中位数 **46.40 → 48.55 MiB**，不声称节省了峰值内存。两版退出码均为 `1`，整份报告逐字节相同（974 条错误，9,410 条警告）；这是诊断等价，不是语料零错误。

## 复跑与边界

- 保留四份独立源码/target，使用同一 `benches/wire_check.rs` 和 Cargo.lock；各自执行 `cargo build --locked --release --bench wire_check --bin tblgen`。`fast` 借用分区名，先比原串，两者全 ASCII 时用 `eq_ignore_ascii_case`，否则沿用 Unicode 比较；`hash` 总是建大写集合；`cursor` 失配才建；这三版都不含延迟格式化。不要拿缺少上轮血缘缓存的裸 `HEAD` 作基线。
- 以下命令对每个输入先比完整有序诊断，再预热；8 轮中每版各占每个运行位置两次。`reordered:256` 必须无诊断，`missing:256` 必须恰好得到 37 个、位置为 `0,7,…,252` 的输出分区错误。

  ```bash
  python3 scripts/compare_wire_check.py "$BASE" "$CURSOR" \
    --variant fast "$FAST" --variant hash "$HASH" \
    --experiment "$EXPERIMENT_TBL" --corpus "$CORPUS_JSON" \
    --case width:256 64 --case width:1024 20 \
    --case reordered:256 64 --case missing:256 64 > four-way.json
  ```

- 延迟格式化独立对照：位置参数换成 `"$CURSOR" "$FINAL"`，去掉 `--variant`，四个 `--case` 的重复次数依次换成 `128,64,128,128`，其余不变。两阶段中位数有机器波动，不相乘当作端到端提速。
- 以上是单机 macOS arm64、热文件缓存测量。若目标转为 CLI 吞吐，可先把 JSON 解析、跨文件引用检查和报告输出分开计时，再决定要不要试 SIMD 解析；本轮没有测试那些阶段的单独耗时。
